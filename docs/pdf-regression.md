# PDF 排版验证

[返回开发指南](development.md#验证改动)

用于修改 PDF 提取、排版、公式保护或导出逻辑后，检查真实扩展的完整处理流程。样本来源、抽查页及保留区域由 [pdf-corpus.json](../tests/fixtures/pdf-corpus.json) 统一维护。

## 质量目标与支持边界

质量判断分为提取、段落组织、翻译保护、实际排版和导出五层。每个逻辑段落保留其物理区域，跨栏、跨页和插图绕排分别处理；公式、引用、数字及已有不可识别区域保留原始内容。译文按浏览器实际字体测量，在原始可读字号范围内调整，完成整页后再检查相邻文字是否碰撞。

不能把“请求成功”或“文字框未溢出”等同于正确的 PDF。保留区域同时检查底图像素和叠加译文；图像版与可搜索版导出都检查当前文字，包含用户编辑后的溢出和重叠。无法完整排入原版面的区域会标出并说明原因，阻止不完整导出，用户可调整文字或区域后重试。自动缩放以原始推荐字号的 60% 为下限，不反复缩到无法阅读。

可搜索导出逐段检查字体是否包含实际字符。缺字的页面保留浏览器中的完整图像，避免出现方框；只为受支持文字添加搜索层，并在下载完成后提示相关页数和搜索限制。验证使用小型字体子集，主动覆盖缺少中文标点及全部字符均不受支持的情况，不额外下载完整字体。字符可搜索不等于字形正确，独立阅读器抽查不可用文字提取代替。

这套质量门槛不承诺所有 PDF 都能保持原版式。扫描页保留图像，目前没有接入 PDF 整页 OCR；没有可靠文字层、严重损坏或无法可靠识别的内容不能被视为翻译成功。极长译文的自动重排分页、图表全部文字的语义理解，以及真实服务的翻译准确性也不属于当前保证。后续接入版面识别或 OCR 时，仍须通过同一套保护和导出检查，不能以模型输出代替验证。

完整方案应提供两条输出路线：结构可靠且空间足够的区域保持原版式；空间不足或结构不确定的内容采用可阅读的重排版式，并能回到原页核对。要求任意长度的译文都塞进同一张原版页面，会把问题转化为缩字、重叠或缺字，不能作为可靠性目标。

后续架构仍有明确工作，而不是增加样本后宣称通用支持：

| 层次 | 当前实现 | 完整路线 |
| --- | --- | --- |
| 文档结构 | 文字区域、公式、单元格、段落与跨页关联 | 统一正文、标题、图表、图注、脚注及阅读顺序的中间表示，记录源区域和识别置信度；识别器与翻译器分离 |
| 版面识别 | 基于文字位置、样式、路径和字体用途的结构判断 | 为复杂混排提供可选版面模型，输出仍受原图和保护规则约束；不将未经验证的模型推断直接当成正文 |
| 超长译文 | 在可读字号下修复，失败时标记并阻止不完整导出 | 增加独立的重排导出，允许新增页和清晰的源页映射，完整保留译文，独立验证页数与内容完整性 |
| 扫描与混合页 | 图像页保留原图，文字页独立翻译 | 按页检测并接入可选 OCR，保留识别置信度与校正入口；低置信度结果不标为成功 |
| 字体与脚本 | 缺字页面图像降级并提示搜索限制 | 按目标语言选择受校验的字体包，对复杂文字按完整字形序列排版，保留图像导出作为可靠后备 |
| 超大文档 | 按阅读位置渲染，当前基线最长 43 页 | 增加资源限额、离屏画布回收与分段导出，独立测试数百页文档和资源不足场景，不以小样本推断大文档稳定性 |
| 语言质量 | 本地模拟译文检验流程、标记及版式 | 为真实服务建立经核对的双语段落、术语表与数字/单位检查；语义质量独立评审，不用几何通过率替代 |

下一批样本还应补充非学术年报、表单票据、目录、竖排与从右向左文字。当前的 12 份文档是可重复的学术与技术文档基线，不代表覆盖了所有文档类型。

## 批量专项验证

`npm run test:pdf:quality` 使用独立浏览器、本地生成样本和本地模拟翻译服务。真实样本目前为 12 份、198 页，覆盖学术论文、讲义、技术规格书、双栏、代码、公式、表格、混合字体和长文档。所有真实样本固定 SHA-256；下载页变成验证页面或文件发生变化时直接失败，需核对后再更新样本，不自动接受新文件。

```bash
# 无外部 PDF 下载的基础验证：绕排、表格、引用、裁剪、旋转、三栏、图像页及两种导出
npm run test:pdf:quality -- --profile=smoke

# 全部真实文档，逐页检查与可搜索导出；已有样本时无需 --download
npm run test:pdf:quality -- --profile=standard --download

# 完整矩阵：标准译文、较长译文、三个复杂样本的匿名字体变体
npm run test:pdf:quality -- --profile=full --download --workers=2

# 针对不同浏览器或一组问题文档
npm run test:pdf:quality -- --profile=standard --browsers=chrome,edge,firefox --ids=attention,drg
```

`standard` 必须完整排版、无重叠并成功导出。`stress` 使用约为源文字符数 65% 的中文测试内容；`full` 包含两种长度和匿名字体测试。压力测试区分“排版成功”与“安全拦截”：后者必须有可见提示、问题标记，并实际尝试导出验证被阻止，不能算作成功生成译文 PDF。未被发现的问题、静默裁切、未标注重叠、异常字符或程序错误始终失败。

每组运行相互隔离，一份失败不会跳过其余样本。可读报告为 `.npm-cache/pdf-quality/<profile>/report.html`，完整数据为同目录 `report.json`；各样本目录保留逐页文字几何、失败页截图、来源保留区域和日志。报告分别列出正常排版、安全拦截和失败数量，不以重复运行页数冒充独立样本页数。

自动检查仍有边界：只有指定保留区域进行像素比较，坐标检查不能证明全部阅读顺序或译文意思正确。新增问题必须保留最小复现样本或公开原文，并增加能识别该问题的检查；抽查截图和独立阅读器检查导出文件仍不可省略。版面信息与语言内容分离的设计可参考 [BabelDOC 论文](https://aclanthology.org/2026.acl-demo.25/)，不同文档类型的覆盖问题可参考 [DocLayNet 论文](https://arxiv.org/abs/2206.01062)。

## 运行

先按[开发指南](development.md#环境搭建)安装项目依赖，再准备可选的浏览器测试环境：

```bash
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run build
npm run test:pdf -- --download
```

`--download` 在本地缺少样本时下载公开 PDF；已有缓存后可省略。测试使用独立浏览器资料和本地模拟翻译服务。

`drg` 样本逐像素检查第 4 页表 3 的条件列和计数列、第 8–10 页的公式，以及第 11 页的双栏参考文献。表 3 检查跨行条件和相邻数值的原始位置。第 10 页分别检查式 (18)、(19)，第 11 页的检查包括第一条编号和右栏开头的续排条目。若出版方下载页要求浏览器验证，可手动下载原始英文 PDF，保存为 `.npm-cache/pdf-corpus/drg.pdf`，再运行 `npm run test:pdf -- --ids=drg`。

`sn74lv1t34` 样本覆盖有格线和跨行表头的技术规格表。第 5、7 页逐像素检查数值和单位，并在学术 PDF 浏览器验证中检查中文表头的单元格位置和字色对比。运行 `npm run test:pdf -- --download --ids=sn74lv1t34` 可单独检查该样本。

学术 PDF 验证也支持 `--corpus=drg`，复用缓存样本和公式保留区域。例如 `npm run test:pdf:academic:firefox -- --corpus=drg` 可在 Firefox 中检查预览、公式像素及可搜索导出。

学术 PDF 的本地样本还覆盖插图旁的摘要绕排、装饰方块标题和使用不同连字符或分散字符的上标引用，检查译文不覆盖插图、标题字号及正文段落保持正常。

斜向水印和旋转图表标签通过透明字形层保留，不复制外接矩形内的正文，也不作为译文的排版障碍或翻译上下文。无网络样本包含两个与正文交叠的斜向水印、竖排标签和独立图形，检查背景中没有被复制的原文，并分别验证图像版和可搜索版导出；生成的 `watermark-export.png` 用于检查水印颜色、方向及正文可读性。

增加 `--anonymize-fonts` 会再检查一份隐藏字体名称的样本，验证公式保护不依赖出版方字体名。测试只修改本地副本的字体名称，保留嵌入字体与页面内容，并核对原公式区域的渲染哈希。示例：`npm run test:pdf:academic:firefox -- --corpus=drg --anonymize-fonts`。

公式识别综合使用上下标位置、相邻表达式、分数线、当前页字体的用途及异常编码证据，已知数学字体作为补充。检测到异常编码的文本片段保留原图，不尝试按字符猜测数学含义。含文字的行内分式也按排版结构保护，并检查其分子、分母没有进入翻译请求。分段公式根据左侧关系式、括号和对齐的多行分支整体保护，包括其中的函数名与条件文字。单元测试同时覆盖普通正文、连字、小型大写标题、表格和日期，防止保护范围扩散。

可通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 的 `index.mjs`，通过 `PDF_TEST_BROWSER` 指定 Chromium 或 Edge 的可执行文件。

## 常用参数

参数放在 `npm run test:pdf --` 后，按需要组合。

| 参数 | 用途 |
| --- | --- |
| `--ids=admm,pmlr` | 仅检查指定样本，标识见样本清单 |
| `--file="/absolute/path/paper.pdf"` | 加入本地问题文档 |
| `--expanded` | 使用较长模拟译文检查排版 |
| `--device-scale=1.25` | 检查屏幕缩放对显示与导出的影响 |
| `--auto-open` | 通过 URL 打开文档并自动开始翻译 |
| `--repeat=3` | 重复操作，检查译文与缓存复用 |
| `--minimum-font=48` | 在测试资料中模拟浏览器最小字号限制 |
| `--damage-markers` | 模拟公式标记损坏，检查恢复流程 |

例如，使用已缓存的讲义检查缩放、自动打开与重复翻译：

```bash
npm run test:pdf -- --ids=admm --device-scale=1.25 --auto-open --repeat=3
```

## 翻译任务与超时

修改 PDF 请求、取消任务或后台连接时，运行对应浏览器的生命周期验证：

```bash
npm run build
npm run test:pdf-lifetime:edge
npm run build:firefox
npm run test:pdf-lifetime:firefox
```

测试生成三页 PDF，使用本地服务模拟不返回正文、延迟 35 秒回复与正常回复，检查超时后终止网络请求、失败部分重试、切换语言及离开页面时取消旧任务，并确认后台队列清空。测试会缩短阅读器的等待时间；后台单批次任务的两分钟期限、排队取消和公式标记恢复期间的取消由 `tests/pdf-translation.test.ts` 覆盖。报告保存在 `.npm-cache/pdf-lifetime/`。

`npm run test:pdf-partial:edge` 与 `npm run test:pdf-partial:firefox` 使用多段落 PDF，主动截断 HTTP 回复正文，检查成功段落立即显示、自动重试有上限、按页补译只发送缺失段落、手动修改及输入焦点保留，以及跳页后取消远处请求并优先处理新阅读页。报告与部分失败截图保存在 `.npm-cache/pdf-partial/`。

## 结果与边界

样本文件、各运行模式的 `report.json` 和对照截图保存在 `.npm-cache/pdf-corpus/`，不随源码提交。报告检查失败页、文字溢出、字号、导出页数与尺寸；部分样本还比较公式和图表区域的像素。

验证后应人工查看重点截图，并用独立 PDF 阅读器抽查导出文件。模拟译文用于重复验证流程与排版，真实服务的翻译质量和网络行为需另行检查；扫描 PDF 的 OCR 不在这组验证范围内。
